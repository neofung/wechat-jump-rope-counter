# PRJ-001 端侧识别验证原型

用于验证「微信小程序 + 前置摄像头 + VisionKit Body 关键点 + 起跳计数状态机」的可行性。只做识别与计数验证，不包含产品级 UI、语音、历史记录。

## 目录

```text
prototype/
├── project.config.json          # 微信开发者工具项目配置
├── miniprogram/
│   ├── app.js / app.json / app.wxss
│   ├── sitemap.json
│   ├── pages/index/             # 验证页：前摄、检测、计数、日志
│   └── utils/counting.js        # 起跳计数状态机（可复用于产品）
└── tests/counting.test.js       # 合成关键点序列单元测试
```

## 技术路径

`camera`（前置）→ `CameraContext.onCameraFrame` 取 RGBA 帧 → 限频 → `VKSession.detectBody({ sourceType: 0 })` → `updateAnchors` 23 点关键点 → 置信度过滤/EMA → `JumpCounter` 状态机 → 计数与调试日志。

## 真机验证步骤（脱敏版）

> 本文档与示例配置不包含真实 AppID、账号、手机号或设备标识。请使用你自己的 AppID，并避免把真实 AppID 提交到版本库。

### 1. 前置条件

| 项 | 要求 |
|----|------|
| 小程序 AppID | `<YOUR_APPID>`；当前开发者账号需有管理员或开发者权限 |
| 微信开发者工具 | 已安装并登录该 AppID 的账号 |
| 手机 | Android 10+ 或 iOS 14+，微信 8.0.30+ |
| 基础库 | ≥ 2.28.0（VisionKit Body 要求），建议 3.x |
| 隐私指引 | 小程序后台「设置 → 服务内容声明 → 用户隐私保护指引」中声明摄像头用途 |
| 场地 | 手机支架、真实跳绳、2–3 米空间、正常室内光照 |

### 2. 导入与配置

1. 将 `project.config.json` 的 `appid` 改为 `<YOUR_APPID>`，或在导入项目时填写。
2. 真实 AppID 仅保留在本地；提交前改回 `touristappid` 或占位符。
3. 开发者工具「导入项目」选择 `prototype/`，不使用云服务。
4. 「详情 → 本地设置 → 调试基础库」选择 ≥ 2.28.0（建议 3.x）。
5. 编译一次，确认无报错。

### 3. 真机调试

1. 顶部点「真机调试」（不是「预览」），用手机微信扫码。
2. 手机上允许摄像头权限。
3. 手机固定在支架上，距用户 2–3 米，前置摄像头覆盖全身。
4. 点「开始」，保持静止约 1 秒，直到状态从「保持静止校准…」变为「着地」。
5. 点「显示索引」，核对踝 15/16、髋 11/12、膝 13/14；举右手确认镜像方向。
6. 开始跳绳，观察计数、检测帧率与关键点。

> 模拟器不支持真机摄像头/VisionKit 能力，必须用真机调试。

### 4. 最小验证闭环

先跑以下四项，确认链路可用：

| 步骤 | 操作 | 通过标准 |
|------|------|---------|
| E1 | 打开页面，点开始，观察关键点与计数 | 收到关键点，检测帧率 ≥ 10fps |
| E2 | 显示索引，核对 15/16 踝、11/12 髋、13/14 膝 | 点位与身体部位对应 |
| E2 | 举右手 | 预览与关键点方向一致；不一致时切换「镜像开/关」 |
| E3 | 并跳 30 秒，人工对照 | 差值 ≤ 2 次 |
| E4 | 双摇 30 次起跳 | 计数约 30，不是 60 |

E1/E2 不通过时先停止后续测试，记录控制台报错与现象。

### 5. 完整测试

按 [recognition-validation.md](../PRJ-001/06-technical-design/recognition-validation.md) 执行 E3–E7：

- 并跳、交替跳各 1 分钟 ×5；交叉跳、双摇各 30 次 ×5；混合跳 1 分钟 ×3。
- 无绳空跳：手臂静止（应为 0 次）、甩腕（记录误计率）、真绳对照。
- 环境：正常光/逆光/弱光；1.5 / 2.5 / 3.5 米；正面/侧面 30°。
- 性能：连续跑 30 秒 + 1 分钟 + 3 分钟，记录帧率、发热、耗电。

### 6. 日志回传与脱敏

1. 点「复制日志」，日志会复制到手机剪贴板。
2. 通过微信「文件传输助手」发到电脑，保存为 JSON。
3. 文件名使用 `日期-设备代号-测试项-跳法-时长-人工计数.json`，不要包含姓名、手机号、账号。
4. 日志仅含关键点、计数与信号，不含摄像头画面；不要额外共享含人脸的视频或截图，除非必要并已脱敏。
5. 记录设备信息时只写型号、系统版本、微信版本、基础库版本，不记录设备序列号。

### 7. 常见问题

| 现象 | 处理 |
|------|------|
| `wx.createVKSession` 不存在 | 基础库低于 2.28.0，升级调试基础库 |
| VisionKit 启动失败 | 检查真实 AppID、微信版本、摄像头权限 |
| 一直收不到关键点 | 确认全身入镜、光线正常、`frame-size` 为 medium；查看 `detectBody` 报错 |
| 摄像头黑屏 | 权限被拒；到小程序设置中开启摄像头，或检查隐私指引 |
| 检测帧率低 | 把处理帧率降到 10fps；关闭后台应用；后续可换 small 帧尺寸 |
| 关键点方向反了 | 切换「镜像开/关」；确认 `device-position="front"` |
| 屏幕自动熄灭 | 延长系统自动锁屏时间；产品阶段会加常亮 |

## 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| 起跳阈值 | 6% | 髋部上升超过躯干高度的 6% 判为起跳 |
| 处理帧率 | 15fps | 调用 `detectBody` 的频率 |
| 手腕筛选 | 关闭 | 开启后要求腕部有明显活动，用于无绳筛选实验 |
| 镜像关键点 | 开启 | 前摄预览镜像时使用 |
| 校准时长 | 1s | 开始计数前静止校准基线 |

## 单元测试

```bash
node tests/counting.test.js
```

覆盖：正常计数、小幅晃动不计数、双摇计 1 次、无绳（手臂静止）不计数、无绳（甩腕）已知误计、踝关键点缺失回退、reset、校准期不计数。

> 注意：单元测试使用合成关键点序列，只验证计数逻辑，不替代真机视觉验证。

## 已知限制

- 无绳甩腕仍可能被计数，需要后续时序分类器或绳子检测。
- 开发者工具模拟器不支持真机摄像头/VisionKit 能力。
- 前摄镜像方向需在真机上用「举右手」确认。
- 阈值与处理帧率是初始值，需按真机日志调整。
- 未实现语音、结果页、历史与个人最佳。

详细验证步骤见 [recognition-validation.md](../PRJ-001/06-technical-design/recognition-validation.md)；技术方案见 [technical-design.md](../PRJ-001/06-technical-design/technical-design.md)。
