## 1. 验证目标

验证以下五个问题，决定产品是否按 VisionKit 方案继续：

1. **平台可用性**：前置摄像头 + `onCameraFrame` + `VKSession.detectBody` 能否在真机稳定输出 23 点关键点？
2. **实时性**：检测帧率、延迟、连续运行稳定性是否满足 NFR-PERF-001/002、NFR-REL-001/005？
3. **计数准确性**：四种跳法下，计数能否达到 1 分钟 100 次误差 ≤ ±5 次（REQ-012）？
4. **口径正确性**：双摇是否按起跳计 1 次？无绳空跳能否被排除？
5. **环境鲁棒性**：光照、距离、角度变化下的退化程度是否可接受？

---

## 2. 验证环境

### 2.1 设备

| 项 | 要求 |
|----|------|
| Android | 至少 1 台，Android 10+，微信 8.0.30+ |
| iOS | 至少 1 台，iOS 14+，微信 8.0.30+ |
| 基础库 | ≥ 2.28.0（VisionKit Body） |
| 支架 | 手机固定支架，前置摄像头朝向用户 |
| 跳绳 | 真实跳绳；无绳空跳用于负向测试 |
| 光照 | 室内常规照明；另测逆光/弱光 |

> 具体机型、微信版本、基础库版本在验证报告中记录并锁定为 NFR-COM-001/002 基线。

### 2.2 场地与机位

- 手机固定高度约 1.2–1.5m，距用户 2–3m，前置摄像头覆盖全身。
- 用户面向手机，画面中仅一人。
- 默认 1 分钟档；单跳法测试可用 30 秒档。

---

## 3. 原型与操作步骤

### 3.1 打开原型

1. 打开微信开发者工具，导入 `prototype/` 目录。
2. 将 `project.config.json` 的 `appid` 替换为你的小程序 AppID（VisionKit 真机能力需要真实 AppID）。
3. 点击「真机调试」，用手机扫码；**不要仅用模拟器**（摄像头/VisionKit 能力受限）。

### 3.2 操作流程

1. 允许摄像头权限，确认画面为前置摄像头。
2. 点击「开始」，保持静止约 1 秒，等待状态从「保持静止校准…」变为「着地」。
3. 点击「显示索引」，确认 0–22 关键点与身体部位对应；用「举右手/抬左腿」确认镜像方向。
4. 开始跳绳；观察计数、髋/踝信号、检测帧率。
5. 结束后点击「复制日志」，将 JSON 粘贴保存为文件，命名规则见 5.1。
6. 同时用另一台手机录像或人工计数，作为 ground truth。

### 3.3 参数

- 起跳阈值：默认 6%；按 2%–15% 调整。
- 处理帧率：默认 15fps；低端机可降至 10fps。
- 手腕筛选：默认关闭；无绳测试时打开。
- 镜像关键点：默认开启；若方向不符则关闭。

## 4. 实验矩阵

### E1 平台可用性与前摄

| 子项 | 操作 | 观测 | 通过标准 |
|------|------|------|---------|
| E1.1 | 路径 B：前摄 + `onCameraFrame` + `detectBody(sourceType:0)` | 是否收到 `updateAnchors`；检测 fps；是否崩溃 | 稳定输出关键点，检测 ≥ 10fps |
| E1.2 | 路径 A：`VKSession` body mode 1，`session.config.cameraPosition=1` | 前摄是否生效；关键点 fps | 前摄生效，fps ≥ 15 |
| E1.3 | 检查 `wx.createInferenceSession` 可用性 | API 是否存在、ONNX 模型能否加载 | 仅记录，不在本轮强制 |

**结论用途**：若 E1.1 不满足，切换 E1.2；若两者都不满足，进入 E8（ONNX 模型）。

### E2 关键点映射与稳定性

| 子项 | 操作 | 观测 | 通过标准 |
|------|------|------|---------|
| E2.1 | 显示索引，逐点核对 0–22 | 部位是否正确 | 踝 15/16、髋 11/12、膝 13/14 可稳定识别 |
| E2.2 | 站立 10 秒，记录关键点抖动 | 归一化抖动幅度 | 踝/髋抖动 ≤ 1% 躯干高度 |
| E2.3 | 2m / 3m 距离 | 关键点置信度 | 踝/髋置信度 ≥ 0.3 |

### E3 计数准确性（核心）

| 子项 | 跳法 | 时长/次数 | 重复 | 通过标准 |
|------|------|----------|------|---------|
| E3.1 | 并跳 | 1 分钟 | 5 次 | 每次 100 次误差 ≤ ±5；连续 5 次均满足 |
| E3.2 | 交替跳 | 1 分钟 | 5 次 | 同上 |
| E3.3 | 交叉跳 | 30 次起跳 | 5 次 | 误差 ≤ 2 次 |
| E3.4 | 双摇 | 30 次起跳 | 5 次 | 误差 ≤ 2 次 |
| E3.5 | 混合跳 | 1 分钟 | 3 次 | 误差 ≤ ±5 |

**记录**：每次测试记录人工计数、原型计数、差值、检测 fps、平均置信度、日志文件名。

### E4 双摇口径

- 连续完成 30 次双摇起跳（每次绳子过脚两次）。
- 期望计数 30 ± 2，而不是约 60。
- 通过标准：计数按起跳次数，不按绳子过脚次数。

### E5 无绳空跳负向测试

| 子项 | 动作 | 期望 |
|------|------|------|
| E5.1 | 无绳空跳、手臂自然下垂 | 计数 0 |
| E5.2 | 无绳空跳、双手模拟摇绳（甩腕） | 计数 0（当前启发式可能失败） |
| E5.3 | 真实跳绳 | 正常计数 |

**通过标准**：E5.1 必须为 0；E5.2 若无法为 0，记录误计率，进入「无绳分类器/绳子检测」决策；未解决前不得对外承诺无绳空跳完全排除。

### E6 环境鲁棒性

| 子项 | 条件 | 通过标准 |
|------|------|---------|
| E6.1 | 正常光照（基线） | E3 标准 |
| E6.2 | 逆光/侧逆光 | 误差 ≤ ±10/100，或明确记录不可用 |
| E6.3 | 弱光 | 误差 ≤ ±10/100，或明确记录不可用 |
| E6.4 | 距离 1.5m / 2.5m / 3.5m | 基线距离附近满足 E3；边缘距离记录退化 |
| E6.5 | 正面 / 侧面 30° | 正面满足 E3；侧面记录退化 |
| E6.6 | 深色/浅色服装各一组 | 不出现关键点持续丢失 |

### E7 性能、发热与耗电

| 子项 | 操作 | 通过标准 |
|------|------|---------|
| E7.1 | 连续完成 30 秒 / 1 分钟 / 3 分钟各一次 | 0 次闪退、0 次计数中断 |
| E7.2 | 记录初始帧率（预热后首 30 秒均值） | 正常阶段识别 ≥ 15fps；热压力期间 ≥ 10fps |
| E7.3 | 测温与电量 | 外壳 ≤ 45℃（环境 25±2℃）；电量消耗 ≤ 15%（起始 ≥ 50%） |
| E7.4 | 内存/CPU | 无持续增长导致崩溃 |

### E8 降级模型（条件触发）

仅在 E1 或 E3 不达标时执行：

1. 选定轻量姿态模型（MoveNet / BlazePose / 自训练）导出 ONNX。
2. 用 `wx.createInferenceSession` 在真机加载，测量推理耗时、帧率、关键点精度。
3. 复用 `JumpCounter` 接口，仅替换感知层。
4. 通过标准：达到 E1/E3 的最低要求，且模型包体与内存可接受。

## 6. 决策门槛

| 门槛 | 条件 | 决策 |
|------|------|------|
| Go | E1.1 或 E1.2 通过；E2 通过；E3.1/E3.2 满足 ±5/100；E4 通过；E7 通过 | 按 VisionKit 方案进入 MVP |
| Conditional Go | E3 基本达标但 E5.2 失败；或 E6 部分场景退化 | 继续 MVP，但增加无绳分类器/绳子检测；在文档中限定支持场景 |
| Fallback | E1 检测 fps < 10，或 E3 误差 > 10/100 | 启动 E8，改用 ONNX 模型；VisionKit 仅作对照 |
| No-Go | 两条路径均无法达到 10fps 或误差 > 10/100；或目标机型严重发热 | 重新评估产品形态/硬件方案 |

## 7. 已知限制

1. **当前单元测试是合成数据**：`prototype/tests/counting.test.js` 只验证状态机逻辑（双摇、噪声、缺失关键点、校准），不能替代真机视觉验证。
2. **无绳甩腕会误计**：现有腕部活动启发式只能排除手臂静止的空跳；甩腕空跳与真绳在关键点层面接近，需要分类器或绳子检测。
3. **开发者工具不支持真机能力**：必须在真机调试中验证 VisionKit 与摄像头帧。
4. **前摄镜像未在真机确认**：原型提供镜像开关，需用「举右手」校准。
5. **原型不含语音、结果页、历史与账号**：这些属于产品阶段，不影响本轮识别验证。
6. **阈值是初始值**：6% 起跳阈值、220ms 去抖、15fps 处理帧率需按真机数据调整。

---

## 8. 验证后输出

1. 验证报告：设备基线、E1–E8 结果、失败场景、日志统计。
2. 锁定 NFR 基线：最低微信版本、目标机型、识别帧率、温度/耗电阈值。
3. 算法结论：是否需要无绳分类器/绳子检测；是否需要 ONNX 降级。
4. 进入 M2 MVP 的开发清单与风险清单。
